# 보유 분류 노트 — 스키마·템플릿

`/stock-analysis:classify` 가 쓰는 노트 형식. 판정 기준(유형 정의·임계값·매도 원칙)의 정본은 Vault 의
`02_Areas/생활/재정관리/투자원칙 v2.md` 다. 이 문서는 **형식만** 정한다 — 기준이 다르면 v2 가 이긴다.

## 위치와 이름

- `$OBSIDIAN_VAULT/03_Resources/주식분석/보유분류/{회사명} 보유분류.md`
- 회사명은 종목분석 문서와 같은 한글 관례 (예: `스페이스X 보유분류.md`). 종목분석 문서와 이름이 겹치지 않게 ` 보유분류` 를 붙인다
- **보유 판단의 정본은 이 노트다.** 리스크관리센터·성과평가팀은 이 폴더의 frontmatter 만 읽는다. 종목분석 문서는 링크로 연결한다

## frontmatter

```yaml
---
tags: [보유분류]
ticker: SPCX
종목명: 스페이스X
보유유형: 적정가형          # 인컴형 | 사유형 | 적정가형 | 재료형 | 지수ETF | 비트코인
기업유형: 적자 고성장        # 흑자 성숙 | 흑자 성장 | 적자 고성장 | 프리레버뉴 | 금융/리츠 | 한국 지주 | ETF
규모: 대형                  # 대형 | 중형 | 소형 | 마이크로 | ETF
시총: 2010                  # $B, 숫자만. ETF 는 비움
수익성: 적자                # 흑자 | 적자 | 매출전 | ETF
섹터: 산업재                # stock-analyst 섹터 표기 11개 중 하나. ETF 는 담은 자산 기준
테마: [우주, AI]            # 같이 움직이는 묶음(섹터 한도 계산용). 없으면 []
배분: 모험                  # 안전 | 모험
요구성장률: 46              # %, 역산 DCF. 계산 불가면 비움
실제성장률: 33              # %, 비교에 쓴 값
적정가하단:                 # 종목분석 문서가 있으면 그 값, 없으면 비움
적정가상단:
자동매수: 가능              # 가능 | 불가
상태: 보유                  # 보유 | 매도완료
판정: 초안                  # 초안 | 확정 (재훈님이 사유를 고치면 확정)
분류일: 2026-09-29
다음재분류: 2027-01-04      # 다음 분기 첫 월요일 (1·4·7·10월)
종목분석: "[[스페이스X]]"    # 없으면 비움
---
```

## 본문

```markdown
# {종목명} ({TICKER}) 보유분류

> 판정: **{보유유형}** · {규모} · {수익성} — {한 줄 근거}

## 투자 사유
- (1~3줄. 왜 들고 있나)

## 훼손 조건
- (확인 가능한 사실만. 가격 하락은 넣지 않는다)

## 경계 신호
- (훼손 전 단계. 자동매수 한 단계 낮춤 계기)

## 재료 목록            ← 재료형만 (적정가형은 선택)
| 재료 | 예상 시점 | 상태 |
|---|---|---|
|  |  | 대기 / 반영 중 / 반영 끝 |

## 판정 근거
- 역산 DCF: 요구 {x}% vs 실제 {y}% → {판정} (`reverse_dcf.py` 출력 한 줄)
- 규모·수익성 출처[^1]

## 이력
- {분류일}: 초안 (Claude)

---

**태그**: #보유분류 #{보유유형}

[^1]: 출처 URL
```

## 유형별로 생략하는 것

| 유형 | 투자 사유·훼손 조건 | 재료 목록 | 역산 DCF |
|---|---|---|---|
| 인컴형 | 필수 (훼손은 배당 중심) | 없음 | 선택 |
| 사유형·적정가형 | 필수 | 적정가형은 선택 | 필수 |
| 재료형 | 필수 | 필수 | 계산 불가면 생략 |
| 지수ETF | 생략 | 없음 | 생략 |
| 비트코인 | 훼손 조건만 (제도 사실) | 없음 | 생략 |

## 매도 완료

전량 매도해도 노트를 지우지 않는다. `상태: 매도완료` 로 바꾸고 `## 이력` 에 날짜·매도 이유를 적는다 (성과평가팀 채점용).
