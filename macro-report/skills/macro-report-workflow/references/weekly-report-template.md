## 출처와 각주

- 본문의 **사실 주장**(수치·사건·발언)마다 각주 `[^n]` 를 단다. 해석 문장에는 달지 않는다
- 각주 번호 = 판단 파일 `sources` 의 `id`. 판단 파일에 없는 출처가 필요하면 판단 파일 단계에서 추가한다
- 각주 정의 형식: `[^n]: 출처명, YYYY-MM-DD — [자체 요약 제목](URL)`
  - 링크 텍스트는 **기사 제목을 복사하지 않고** 자체 요약으로 쓴다
- 수치 근거는 FRED 시리즈 페이지(`https://fred.stlouisfed.org/series/<ID>`)나 데이터 플랫폼 공개 API 경로
- 연합뉴스 헤드라인 파일 자체는 링크하지 않는다 (내부 입력 전용)
- 표 안에서는 각주 번호만 (`[^3]`), 설명은 각주 정의에

## 줄바꿈 규칙 (필수)

v1 쉬운말 보고서(2026-09-28)는 250자 넘는 줄이 37개였다. 분량을 줄이지 말고 줄을 나눈다.

- 불릿 한 항목은 **한두 문장, 150자 안팎**. 넘으면 하위 불릿으로 쪼갠다
  - "상황 / 좋게 보면 / 나쁘게 보면" 같은 항목은 각각 하위 불릿
- 일반 문단은 **2~3문장마다 빈 줄**
- 한 문장·불릿에 숫자 3개 이상을 나열하지 않는다 — 넘으면 불릿이나 표로
- `A — B, C, D` 식 나열은 불릿으로 바꾼다
- 인용 블록(`>`)·콜아웃도 같은 기준. 긴 인용은 여러 줄로
- 단일 줄바꿈은 Obsidian·게시본에서 끊기지 않을 수 있다 → **빈 줄이나 불릿**으로 구분

작성 후 자가 점검:

```bash
awk 'length($0) > 250 && !/^\|/ && !/^\[\^/ && !/^ *[{}"\[\]]/' "<보고서 경로>" | wc -l
```

0 이 될 때까지 나눈다 (표·각주 정의·차트 JSON 은 제외).

## 판단 파일과의 관계

- 보고서의 모든 숫자(확률·비중·점수·경계선)는 판단 파일 JSON 과 **같아야 한다**. 보고서에서 새 판단을 하지 않는다
- 보고서에서 판단이 틀렸다고 느끼면 보고서에서 고치지 말고 판단 파일을 먼저 고친 뒤(검증·채점 재실행) 보고서를 다시 쓴다. 게시 뒤에는 판단 파일을 고치지 않는다
