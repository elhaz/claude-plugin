# PM 페르소나 견적 입력 틀

`si-pm-estimator` 에게 PPT 글자와 함께 주는 파일이다. 세션 scratchpad 에 `pm_brief.md` 로 쓴다.

**넣지 않는 것**: 금액(고객 견적 초안, 이전 산정, 과제 금액), 공수 숫자, 볼트 노트 링크 · 경로, 사용자가 다른 과제에 매긴 값.
쓴 뒤 `원|천원|만원|억|M/D|MD|M/M` 을 찾아 남은 것이 없는지 본다.

---

```markdown
# <과제> 견적용 입력 (PM 페르소나용)

## 1. 시스템과 개발 조건 (사실)

- 무엇을 하는 시스템인가, 누가 쓰는가. 운영 서버 몇 대.
- 실행 환경: 언어 · 프레임워크 판, DB 판. 판 때문에 생기는 제약.
- 개발사가 이 코드를 맡아 온 기간, 시험 환경이 있는가.
- 지금 없는 바탕: (메일 발송, 서버 PDF, 정기 실행, 서버 쪽 권한 검사, 업로드 보안 등)
- 다시 쓸 수 있는 틀: (기존 화면 구조, 공통 부품)

(새 모듈이면: 기술 스택 가정, 기존 시스템과 주고받는 방법, 배포 단위)

## 2. 아키텍처 검토 결과 (코드 기준 사실 · 권고)

(기존 코드일 때만. code-architect-reviewer 결과에서 사실과 권고만 옮긴다)

| 코드 | 그대로 쓰는 것 | 새로 만드는 것 |
|---|---|---|

## 3. 견적 범위 기능 모듈

| 코드 | 기능 모듈 | 내용 |
|---|---|---|

옵션(기본 범위 밖, 따로 산정):

| 코드 | 옵션 |
|---|---|

## 4. 견적 가정

1. (사용자가 고른 가정. 번호는 공수 산정 노트와 같게)
2. ...
N. 고객 질문은 아직 답이 없다. 답이 오면 가정을 고친다.
```
