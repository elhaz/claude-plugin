# 노트 작성 규칙

요청 요약 노트와 공수 산정 노트에 공통으로 쓰는 형식이다. 예시의 철골 · PLM 내용은 예시일 뿐이다.

## 근거 표시

| 표시 | 뜻 |
|---|---|
| `p.N` · `p.N, M` · `p.N\~M` | 제안서 쪽 번호. 자료가 둘 이상이면 접두어(「리비전 p.3」) |
| ① ② | 쪽 안 번호가 PPT 에 있으면 그대로 붙인다(`p.33 ⑤`) |
| 「업계 관행」 | PPT 에 근거가 없는 업계 관행. 고객 답으로 확인할 것 |
| 「추측」 | 자료로 확인하지 못한 짐작 |
| 가정 N | 공수 산정 노트 「0. 입력 자료와 가정」의 번호 |
| 날짜 + 사람 | 사용자가 정한 것: 「(2026-10-30 홍길동)」 |

## 질문

받는 쪽마다 절을 따로 둔다: 「<제안사>에 물어볼 것」, 「<고객 현장>에 물어볼 것」. 절 첫머리에 형식을 한 단락으로 적는다.

```markdown
## A사(제안사)에 물어볼 것

제안서를 쓴 쪽이 답할 질문이다. 현장 실무 질문은 아래 「B사(고객 현장)에 물어볼 것」에 따로 두었다.

항목마다 첫 줄이 질문 하나다. 그 아래에 낯선 말이 있으면 「설명」, 그다음 「근거」, 견적에서 잡은 가정이 있으면 「가정」을 둔다.

### 6.5 설치 요구일 입력

- [ ] **설치 요구일은 Zone 착수일인가, 완료일인가?**
  - 설명: 설치 요구일은 발주사가 「이 Zone 은 이 날까지 세워야 한다」고 정하는 날짜다.
  - 근거: p.21 Zone 하나가 600t 이 넘고, p.20 하루 계획은 96t 이다. 착수일과 완료일 차이가 일주일가량 난다.
  - 가정 4: 착수일.
- [x] **요구일 변경 이력을 남기는가?** 남긴다. PPT 에 있었다.
  - 근거: p.28 에 이전 값과 바뀐 값이 이벤트로 남는다.
```

- 질문 한 줄에 질문 하나. 굵게 쓴다.
- 「설명」은 받는 사람이 모를 수 있는 말을 풀 때만.
- 「근거」는 쪽 번호로. PPT 안에서 말이 다른 곳이면 두 쪽을 다 적는다.
- 「가정」은 공수 산정 노트 번호와 그 값. 정하지 않았으면 「가정: 정하지 않았다. 답을 기다린다」.
- PPT 에 답이 있던 것은 `- [x]` 로 체크하고 「PPT 에 답이 있던 것」 소절로 모은다.
- 우리 해석으로 진행하고 확인만 받을 것은 「우리 해석으로 진행하고 확인만 받을 것」 소절에 둔다.

## 표기 절

PPT 에 번호 체계가 여러 벌이면 노트 맨 앞쪽에 「표기」 절을 둔다.

- 메뉴: 「번호 + 이름」(예: 6.2 현장 인수현황). 어느 번호 체계(현행 · 제안)를 쓰는지 밝힌다.
- 화면: 「화면 N」(PPT 화면 번호). 메뉴 번호와 다르다는 것을 적는다.
- 요청 묶음: 노트가 붙인 이름(가\~사).
- 기능 모듈: 노트가 붙인 코드(G01\~, 옵션 O1\~). 메뉴 · 화면 번호와 겹치지 않는 글자.
- 상태 코드: 저장되는 값이면 PPT 그대로 둔다. 코드 · 무엇의 상태 · 값 · 쪽 표로.

## 용어 표

| 말 | 풀네임 · 원말 | 뜻 |
|---|---|---|
| BOM | Bill of Materials | 부재 목록. Tekla 에서 뽑아 2.1 에 올린다 (p.7) |

- 업계 말, 약어, 제품명, 고객사 고유 말. 고객 DB 에서 확인한 말이면 「(날짜 조회)」.

## 기능 모듈 표

```markdown
### 인수 (라)

| 코드 | 기능 모듈 | 묶음 | 메뉴 · 화면 | 근거 | 메모 |
|---|---|---|---|---|---|
| G04 | 인수 데이터 구조 | 라 | 화면 없음 | p.10, 42 | 출하 완료 때 R0 자동 생성. 인수 단위는 송장 1건(가정 2) |
```

- 기존 시스템을 고치는 일이면 「PPT 단계」 열(제안서의 추진 단계)을 더해도 된다.
- 판 설명을 표 위 불릿으로: 무엇을 더했고(코드), 합쳤고, 옵션으로 돌렸는지, 누가 언제 정했는지.

## 접힌 콜아웃

옛 판 · 결정이 난 묶음은 지우지 않고 접는다. 제목에 판 · 날짜 · 접은 까닭.

```markdown
> [!note]- 견적 전에 정해야 하는 것 (1차 검토) · 2026-10-30 가정으로 정함, 질문은 아래 「물어볼 것」
>
> - **송장 1건이 차 1대인가.** ...
```

- 접힌 콜아웃은 `> [!note]-` 를 쓴다. HTML `<details>` 는 쓰지 않는다.
- 해소된 문제는 취소선과 해소 사유를 같이 둔다: `~~문제~~ 해소: 사유(날짜)`.

## 숫자 표기

- MD 는 소수 한 자리(`5.0`). M/M 은 둘째 자리.
- 범위는 `6\~16 MD` 처럼 `\~` 로 쓴다(볼트에서 취소선 방지).
- 금액은 천 단위 쉼표, 「VAT 별도」를 같이 적는다.
- 줄어드는 값은 `−` (U+2212) 로 쓴다.
