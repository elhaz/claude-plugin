# 제안서 요약 · 공수 산정 절차

고객이 보낸 제안서(PPT)에서 두 노트를 만든다.

- **요청 요약 노트**: 고객이 무엇을 요청하는지, 무엇을 물어야 하는지, 견적 단위(기능 모듈)는 무엇인지.
- **공수 산정 노트(내부용)**: 견적(AI 없이 사람) · 실작업(AI 사용) 두 열, 금액, 옵션, 축소안.

두 사례로 다듬은 절차다. 새 모듈을 만드는 일(원자재 관리 모듈)과 운영 중인 기존 코드를 고치는 일(PLM 고도화) 모두에 맞았다. 아래 예시의 철골 · PLM 용어는 예시일 뿐이다.

## 지키는 원칙

1. **견적은 SI PM 페르소나가 뽑는다.** 세션이 직접 뽑지 않고, 세션 값을 참고 열로도 남기지 않는다. 세션은 이미 앞선 금액과 고객 쪽 견적 초안을 본 상태라 그 숫자에 끌린다.
2. **PM 페르소나에게는 금액 · 공수 줄을 거른 PPT 글자와 견적 입력(brief)만 준다.** 볼트 노트, 다른 견적, 고객 쪽 견적 초안은 주지 않는다.
3. **사람 견적을 먼저 뽑고, 실작업은 그다음 배율로 계산한다.** 실작업에서 거꾸로 견적을 만들지 않는다(예: 실작업 × 1.5).
4. **가정은 사용자가 고른다.** 답이 없는 질문은 선택지(추천 = A)로 보여 주고 사용자가 정한다. 세션이 정하지 않는다.
5. **나간 적 없는 견적은 선례가 아니다.** 형식 · 단가 · 배수의 근거로 쓰지 않는다. 근거는 실제로 나간 견적과 공표 단가 원문뿐이다.
6. **전문가 페르소나의 지적은 PPT 원문으로 대조한 뒤 받는다.** 페르소나는 실제 사람의 의견이 아니다. 「업계 관행」 · 「추측」 표시가 붙은 것은 고객 답으로 확인할 질문으로 돌린다.
7. **합계 · 금액 · 일정은 스크립트로 낸다.** 손으로 더하지 않는다.
8. **볼트 노트 문체**: 한국어 평서체, 짧은 문장, 결론 먼저. 표 앞에 빈 줄, 문서 끝에 구분선과 태그, 부모 노트 링크.

## 준비

- 설정: [config/settings.json](../../config/settings.json) 이 기본값이다(단가, 월평균 근무일, 배율, 반올림, 노트 위치). 바꿀 것은 `~/.claude/proposal-estimate.json`(또는 환경변수 `PROPOSAL_ESTIMATE_CONFIG` 가 가리키는 파일)에 그 키만 적는다. 해가 바뀌면 단가부터 새 공표 원문으로 고친다.
- 볼트 위치: 환경변수 `OBSIDIAN_VAULT`. 없으면 지금 작업 폴더를 볼트로 본다.
- 작업 폴더: 중간 파일(PPT 글자, brief, PM JSON, 검토 원문)은 세션 scratchpad 에 둔다. 볼트에는 노트와 그림만 둔다.
- 스크립트 실행: 플러그인 경로를 `$P` 라 하면 `uv run python $P/scripts/<이름>.py`. PPT 추출만 `uv run --with python-pptx python ...`. 한글 출력이 깨지면 `PYTHONIOENCODING=utf-8` 을 붙인다.

  ```bash
  P="${CLAUDE_PLUGIN_ROOT:-$(ls -d ~/.claude/plugins/cache/elhaz-plugins/proposal-estimate/*/ | sort -V | tail -1)}"
  ```

  PowerShell 이면 `$P = $env:CLAUDE_PLUGIN_ROOT` 이고, 비어 있으면 스킬을 불러올 때 보이는 스킬 폴더에서 두 단계 위가 플러그인 경로다.

## 절차

진행 단계는 사용자에게 매번 한 줄로 알린다. 사용자 결정이 필요한 곳(8, 11, 13)에서는 멈추고 묻는다.

### 1. PPT 글자 추출과 쪽 번호 근거

```bash
uv run --with python-pptx python $P/scripts/ppt_extract.py 제안서.pptx -o ppt_all.txt
```

- 쪽마다 `===== p.N =====` 머리가 붙는다. 노트의 모든 근거는 이 번호로 단다(`p.N`, 범위는 `p.29\~38`).
- 자료가 둘 이상이면 접두어로 구분한다(예: 「리비전 p.3」). 노트 「원본」 절에 파일 경로 · 장 수 · 받은 날을 적는다.
- 판이 바뀌어 쪽이 밀리면 옛 판과 새 판의 대응을 「원본」 절에 적는다.
- 그림 · 화면 캡처만 있는 쪽은 글자가 비어 나온다. 그 쪽은 PPT 를 직접 열어 보고 요약에 적는다.

### 2. 질문 정리 (질문 · 설명 · 근거 · 가정 번호)

PPT 에 설명이 없거나 PPT 안에서 말이 서로 다른 곳을 질문으로 만든다. 형식은 [references/note-conventions.md](references/note-conventions.md) 「질문」 절이다.

- **받는 쪽별로 나눈다.** 제안서를 쓴 쪽(제안사 · 원청)이 답할 것과 실제 현장(고객 실무)이 답할 것을 다른 절에 둔다.
- **PPT 근거 검사**: 질문을 올리기 전에 PPT 전체에서 답을 찾는다. 답이 있으면 체크(`- [x]`)하고 답과 쪽을 적어 「PPT 에 답이 있던 것」으로 옮긴다. 일부만 있으면 남은 부분만 질문으로 남긴다.
- 견적 구조를 바꾸는 질문(데이터 기준 단위, 승인 주체, 진행률 기준 등)을 맨 앞에 둔다.

### 3. 표기 분리 · 용어 표

- **표기**: PPT 에는 번호가 여러 벌 섞인다(현행 메뉴 번호, 제안 메뉴 번호, 화면 번호, 상태 코드). 노트가 쓸 규칙을 「표기」 절에 먼저 정한다. 기능 모듈 코드는 메뉴 · 화면 번호와 겹치지 않는 글자로 새로 붙인다(예: G01, F01).
- **용어 표**: 말 · 풀네임(원말) · 뜻. 업계 말, 약어, 제품명, 저장되는 상태 코드. 뜻 끝에 쪽 번호.

### 4. 기능 모듈 표

견적 단위다. 묶음(업무 흐름 순)별 소절로 나누고 열은 다음과 같다.

| 코드 | 기능 모듈 | 묶음 | 메뉴 · 화면 | 근거 | 메모 |
|---|---|---|---|---|---|

- 근거는 쪽 번호, 검토 이름(「아키텍처 검토」 · 「현장 검토」 · 「PM 모듈 검토」), 가정 번호 가운데 하나다.
- 공통 바탕(권한, 알림, 업로드, 정기 실행, 감사 기록 등)은 「바탕 · 공통」 소절에 둔다.
- 쪼갠 모듈은 하위 번호(`G06-1`), 합친 모듈은 번호를 비워 둔다. 지운 모듈은 취소선으로 남긴다.
- 「기본 범위 밖 (옵션)」 표를 따로 둔다(코드 O1\~).
- 판이 바뀌면 제목에 판 · 날짜를 단다: 「기능 모듈 (견적 단위, 2판 2026-10-30)」.

### 5. 1차 전문가 검토

두 서브에이전트를 **동시에** 띄운다. 입력은 PPT 글자 파일과 요약 노트 경로다.

- `proposal-estimate:domain-practitioner`: 역할을 프롬프트에 준다(예: 「철골 제작사 출하 · 운송 · 현장 인수 · 설치 실무 책임자」). 금액이 적힌 쪽은 빼고 준다.
- `proposal-estimate:code-architect-reviewer`: **기존 코드를 고치는 일일 때만.** 대상 코드 경로(와 DB 사본 · 스키마 위치)를 준다. 새 모듈이면 띄우지 않는다.

결과를 받으면:

- 원문은 손대지 않고 「검토 원문」 노트에 그대로 둔다(요약 노트에서 링크).
- **지적의 사실 부분을 PPT 원문으로 대조한다.** 쪽 번호가 맞는지, 숫자가 맞는지. 대조한 예를 요약 노트에 한두 개 적는다.
- 반영할 것은 모듈 표 · 질문에 넣고, 요약 노트 「전문가 검토」 절에 반영 내용을 적는다.

### 6. 레인 그림

diagram-design 플러그인 형식(`*.dd.html` → `*.dd.png`)의 레인형 그림이다. 한 줄 = 한 메뉴, 상자 = 업무 하나, 맨 위 띠 = 요청 묶음, 왼쪽에서 오른쪽 = 일이 거치는 순서. 상자 태그 = 기능 모듈 코드.

```bash
uv run python $P/scripts/lane_diagram.py lane_spec.json -o "$VAULT/05_Attachments/첨부파일/<이름>.dd.html"
```

- 명세 형식은 [examples/lane_spec_example.json](../../examples/lane_spec_example.json). 선 종류: `main`(일 흐름) · `back`(되돌림, 점선) · `link`(입력 · 판정) · `focus` · `focus-dash`(핵심 고리).
- 선이 겹치면 `from_dx` · `to_dx`(가로로 비킴), 라벨은 `label_dx` · `label_dy` 로 옮긴다. 레인 · 열 배치부터 고치는 편이 대개 낫다.
- PNG 는 `/diagram-design:export-diagram` 이나 볼트의 래스터 스크립트로 뽑는다. 뽑은 PNG 는 **반드시 열어서 본다**(선 겹침, 라벨 가림).
- 공통 바탕처럼 흐름이 없는 모듈은 그림에서 빼고 그 사실을 그림 위 안내 줄(`note`)에 적는다.
- 노트에는 `![[<이름>.dd.png]]` 와 그림 읽는 법 한 단락, 그리고 흐름 요약 불릿(일 흐름 · 되돌아가는 길 · 보는 화면 · 고리)을 둔다.

### 7. 2차 검토

`domain-practitioner` 를 2차 모드로 다시 띄운다. 입력: 그림 PNG, 모듈 표, (8단계를 먼저 했다면) 견적 가정.

- 그림 지적은 PPT 원문과 대조해 맞는 것만 그림에 반영한다.
- 반영하면서 새로 생긴 문제는 「사용자 결정 대기」로 적고 8단계 선택지에 올린다.
- 2차 검토가 짚은 **견적 빈칸**(모듈 표에 없는 업무)은 13단계에서 PM 견적 근거와 대조할 목록으로 남긴다.

### 8. 가정 고르기 (사용자)

답이 아직 없는 질문마다 견적이 기댈 가정이 필요하다. 세션이 정하지 않는다.

- 질문마다 선택지 2\~4개를 만든다. **A 가 추천**이고, 추천 이유를 한 줄 단다. 근거는 PPT 쪽 번호.
- AskUserQuestion 으로 한 번에 1\~4개씩 묻는다(많으면 견적 구조를 바꾸는 것부터).
- 정한 가정은 공수 산정 노트 「0. 입력 자료와 가정」에 번호를 매겨 적고, 질문 쪽에 「가정 N: …」 줄로 연결한다.
- 사용자가 「정하지 않음」을 고르면 그 가정은 「답을 기다린다」로 적고, 증가 요인(5.1)으로 돌린다.

### 9. SI PM 페르소나 사람 견적

1. **PM 에게 줄 PPT 글자**를 따로 뽑는다. 고객 쪽 견적 쪽은 통째로 빼고 금액 · 공수 줄을 거른다.

   ```bash
   uv run --with python-pptx python $P/scripts/ppt_extract.py 제안서.pptx -o pm_ppt.txt --exclude 38 --drop-money --drop-effort
   ```

   `--exclude` 에는 고객 쪽 견적 초안이 있는 쪽과 이번 견적 범위 밖 쪽(다른 과제)을 넣는다. `pm_ppt.txt.dropped.txt` 를 열어 거른 줄을 확인한다. 숫자만 남은 표(공수 표의 행)는 정규식으로 안 걸리니 **그 쪽은 `--exclude` 로 뺀다.** 거른 파일 본문에 금액이 남았는지 한 번 더 찾아본다.
2. **견적 입력(brief)** 을 쓴다. 틀은 [references/pm-brief-template.md](references/pm-brief-template.md). 들어갈 것: 시스템과 개발 조건(사실), 아키텍처 검토 결과(있으면), 견적 범위 기능 모듈 표, 옵션, 가정. **금액 · 이전 견적 · 노트 링크는 넣지 않는다.**
3. `proposal-estimate:si-pm-estimator` 를 견적 모드로 띄운다. 프롬프트에 줄 것: 분야 한 줄(예: 「철골 · 중공업 · 건설 고객 웹 시스템과 PHP 레거시 고도화를 견적해 온 PM」), 등급(설정의 `rate.grade`), 두 입력 파일 경로, 출력 경로(`pm_estimate.json` · `pm_estimate.md`). 「다른 파일은 열지 말라」를 프롬프트에도 적는다.

### 10. 실작업 = 견적 × 일 종류별 배율

PM JSON 의 행마다 `kind` 를 세션이 붙인다(배율은 세션 몫이다). 섹션 단위 기본값(`sections[].kind`)을 쓰고 예외 행만 적어도 된다.

| kind | 일의 종류 | 기본 배율 |
|---|---|---:|
| `dev` | 화면 · 기능 개발 (입력 · 조회 · 출력 · API) · 문서 | 0.45 |
| `logic` | 계산 로직 · 기존 코드 수정 · 서버 구성 · 데이터 이관 · 테스트 | 0.6 |
| `analysis` | 분석 · 설계 · 명세 · 검수 시나리오 | 0.75 |
| `meeting` | 회의 · 교육 (AI 로 줄지 않는다) | 1.0 |

```bash
uv run python $P/scripts/real_effort.py pm_estimate.json -o result.json
```

- 0.5 MD 단위로 반올림한다(사사오입). 회의(`meetings`)는 견적 = 실작업이다.
- kind 가 빠진 행이 있으면 스크립트가 멈추고 목록을 보여 준다.
- 배율은 가정이다. 노트에 그렇게 적고, 실제 작업 기록이 쌓이면 설정 파일의 배율을 고친다.

### 11. PM 모듈 검토와 반영

`si-pm-estimator` 를 모듈 검토 모드로 띄운다(입력: 같은 brief · PPT 글자 + `pm_estimate.json`). 결과(더할 것 · 합칠 것 · 쪼갤 것 · 빼거나 옵션 · 빠진 화면 · 축소안 후보)를 받으면:

- **사용자가 정한 가정과 부딪히는 권고는 반영하기 전에 사용자에게 묻는다.** 검토가 「가정 N 과 충돌」로 표시한다.
- 부딪히지 않는 권고는 묶어서 「제안대로 반영할까요?」 한 번으로 묻는다.
- 반영은 PM 에게 부분 재산정(모드 3)을 시키거나, 검토 문서의 MD 를 JSON 에 옮긴다. 세션이 새 MD 를 만들지 않는다.
- 모듈 표(요약 노트)도 같은 판으로 고친다. 더한 모듈 · 합친 모듈 · 옵션으로 돌린 모듈을 판 설명에 적는다.

### 12. 옵션 · 늘어나는 요인 · 1차 오픈 축소안 · 하자보수 → 노트 채우기

1. 템플릿 [references/estimate-note-template.md](references/estimate-note-template.md) 을 볼트 노트 자리에 복사한다.
2. `<<적을 것: ...>>` 자리를 세션이 글로 채운다(부모 링크, 입력 자료, 가정, 착수 전 정할 것, 견적서 품목, 변경 이력).
3. 숫자 자리 `{{...}}` 는 스크립트가 채운다.

   ```bash
   uv run python $P/scripts/fill_note.py 노트초안.md pm_estimate.json result.json -o "<볼트>/.../YYYY-MM-DD <과제> 공수 산정.md"
   ```

- 축소안은 기본 견적에서 빼지 않고 따로 둔다. 쓰지 않기로 한 축소안 행은 JSON 에 `"rejected": true, "reason": "..."` 를 달면 취소선으로 남는다.
- 하자보수 · 안정화는 기본 합계 밖 한 줄이다(`warranty`).
- 남은 자리가 있으면 스크립트가 멈춘다. 쓸 수 있는 자리 이름은 `fill_note.py --list`.
- 견적서 작성 안내(7절): 「식」 단위 · VAT 별도, MD · 단가는 견적서에 적지 않는다.

### 13. 2차 검토가 짚은 견적 빈칸 대조

7단계에서 남긴 빈칸 목록을 PM 견적 전문(`pm_estimate.md`)의 행 근거와 하나씩 대조한다.

- 이미 들어 있으면 「들어 있었다(행 id)」로 요약 노트 2차 검토 절에 적는다.
- 빠졌으면 사용자에게 보여 주고, 넣기로 하면 PM 부분 재산정으로 행을 더한다. 그 뒤 10 · 12단계를 다시 돌린다.

### 14. 오래된 판은 접힌 콜아웃으로

판이 바뀔 때(모듈 표 2판, 그림 2판, 가정 변경) 옛 내용을 지우지 않는다.

```markdown
> [!note]- 1판 그림 (2026-10-23, 모듈 표 전에 그림 · 접어 둠)
>
> ![[옛그림.dd.png]]
```

- 콜아웃 제목에 판 · 날짜 · 왜 접었는지를 적는다. 결정이 난 질문 묶음도 「정했다: 가정 N」 꼬리를 달아 접는다.
- 공수 산정 노트는 맨 끝 「변경 이력」 표에 날짜 · 바뀐 것 · 새 합계를 한 줄씩 쌓는다.

## 답이 온 뒤 (재산정)

고객 답이 오면 질문을 체크하고 답을 적는다. 바뀐 가정만 PM 부분 재산정에 보낸 뒤 10 · 12단계를 다시 돌린다. 변경 이력에 「가정 N: 바뀐 내용, 견적 X → Y MD」를 적는다.
